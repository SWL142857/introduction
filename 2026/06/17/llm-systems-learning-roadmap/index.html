LLM Systems 学习路线：从 MiniTorch 到 RLHF

发表于2026-06-17|更新于2026-06-17|Learning
|浏览量:

如果只停留在 API 调用层，大模型很像一个黑盒服务：传 prompt，等返回。但 LLM Systems 学习的价值在于把这个黑盒拆开：自动微分怎么跑、CUDA kernel 怎么写、Transformer 怎么实现、分布式训练怎么切、推理系统怎么缓存、RLHF 怎么组织。

我的系统学习材料主要来自 cmu11868/、cmu11766/、homework_spring2026/、CS185:285/ 和 RL-notes/。

第一层：自动微分和张量框架

cmu11868/hw1 从 MiniTorch 开始，任务是实现自动微分、简单神经网络和训练流程。这里最重要的不是写一个玩具框架，而是理解现代深度学习框架的基本抽象：

  • Variable / Tensor 如何构成计算图。
  • topological sort 如何保证反向传播顺序。
  • backpropagate 如何沿图累计梯度。
  • 梯度为什么要初始化和清零。

很多后续 bug 都会回到这里。比如梯度初始化不正确，可能在更复杂的 Transformer 作业中表现成完全不相关的 backward 测试失败。

第二层：CUDA 和 GPU kernel

cmu11868/hw2 进入 CUDA 编程：map、zip、reduce、矩阵乘法和 Python 后端集成。

这一层训练的是硬件意识：

  • thread/block/grid 的维度如何设计。
  • tensor shape 和 memory layout 如何影响 kernel。
  • batch 维度、m/p 维度写错会造成什么后果。
  • CPU/GPU 数据移动为什么昂贵。

LLM 系统里很多性能问题，本质上不是“模型不够聪明”，而是 kernel、显存访问和调度没处理好。

第三层：Transformer 架构

cmu11868/hw3 把 MiniTorch 扩展到 decoder-only Transformer，并在机器翻译任务上训练和 benchmark。

这一层需要把以下模块真正串起来：

  • token embedding 和 position embedding
  • causal self-attention
  • MLP
  • residual connection
  • layer norm
  • cross entropy
  • autoregressive decoding

手写 Transformer 的价值是看见每个张量维度如何流动。读论文时，很多公式很优雅；写代码时，很多错误都来自 shape、mask 和数值稳定性。

第四层：分布式训练

cmu11868/hw5 覆盖 data parallel 和 pipeline parallel。

分布式训练的基本矛盾是：模型越来越大，单卡放不下；数据越来越多，单机跑太慢。常见切法包括：

  • Data Parallel：复制模型，切数据，聚合梯度。
  • Pipeline Parallel：按层切模型，微批次流水执行。
  • Tensor Parallel：切矩阵计算。
  • ZeRO：切 optimizer state、gradient 和 parameter。

学习时最需要注意的是通信成本。并行不是免费加速，all-reduce、stage bubble、显存碎片和负载不均都会吞掉收益。

第五层：高效训练与推理

cmu11868/hw6 涉及 DeepSpeed ZeRO、LoRA 和 SGLang。

LoRA 的思路是冻结大部分原模型参数，只训练低秩增量，从而降低显存和训练成本。ZeRO 则从优化器状态、梯度和参数切分入手，让多卡共同承载训练状态。

SGLang 代表推理系统侧的优化：RadixAttention 复用 KV cache，cache-aware scheduling 提高前缀命中率，constrained decoding 用压缩 FSM 加速结构化输出。

这说明训练和推理是两套不同的系统问题：

  • 训练关注吞吐、显存、梯度、优化器和并行策略。
  • 推理关注延迟、吞吐、KV cache、调度、batching 和输出约束。

第六层：RLHF 与 LLM 后训练

cmu11868/hw7 和 RL-notes/ 把路线推进到 RLHF、PPO、reward model 和 VERL。

RLHF 的核心链路可以写成：

  1. 收集偏好数据。
  2. 训练 reward model。
  3. 用 PPO 等方法优化 policy。
  4. 评估 helpfulness、harmlessness 和任务表现。

这和传统监督学习有明显不同：数据不是固定答案，而是偏好；优化目标不是纯交叉熵，而是奖励、KL 约束和策略稳定性之间的平衡。

我的学习顺序建议

如果重新组织这条学习线，我会按这个顺序：

  1. 自动微分和 MiniTorch：理解框架底座。
  2. CUDA kernel：建立硬件和并行计算直觉。
  3. Transformer：把模型结构写清楚。
  4. 分布式训练：理解大模型为什么需要系统工程。
  5. 推理系统：理解服务端瓶颈和 cache 复用。
  6. RLHF / Agentic RL：理解模型如何从预测走向决策。

这条路线的目标不是成为每一层的专家，而是建立跨层判断：一个 LLM 应用慢、贵、不稳定、不可控时，问题可能出现在数据、模型、训练、推理、调度、评估或产品状态机的任意一层。
