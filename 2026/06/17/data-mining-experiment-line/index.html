数据挖掘实验线：从房价预测到合同审阅

发表于2026-06-17|更新于2026-06-17|Learning
|浏览量:

Data Mining/ 这条线不是一个单独项目，而是一组实验：传统机器学习、集成学习、结果分析，以及大模型在合同审阅中的应用。它很适合用来观察一个变化：数据挖掘课程正在从“训练模型”扩展到“设计可验证的 AI 工作流”。

HW2：房价预测与集成学习

HW2 基于 Kaggle House Prices 数据集，任务包括：

  • Linear Regression 做连续房价预测。
  • SVM 和 Logistic Regression 做离散化房价分类。
  • XGBoost 做回归预测。
  • Stacking Ensemble 集成多个回归器。

预处理流程很朴素但完整：

  • 只保留数值型特征。
  • 训练/验证集按 80/20 划分。
  • 缺失值用中位数填补。
  • 房价按 ceil(SalePrice / 100000) 离散化。

结果里，Stacking Ensemble 在 Accuracy、MAE 和 RMSE 上都优于 XGBoost。这个结论本身不惊人，真正值得记录的是实验组织方式：固定 random seed、明确数据划分、同时报告分类和回归指标、把输出保存成 JSON/Markdown。

为什么 Stacking 有用

Stacking 的价值来自模型互补。XGBoost、RandomForest、ExtraTrees、HistGradientBoosting 和 KNN 对数据结构的偏好不同，元学习器再把它们的预测与原始特征结合起来。

但 Stacking 也有风险：

  • 小数据上容易过拟合。
  • 特征预处理不一致会污染结果。
  • 如果 validation set 太少，提升可能只是偶然波动。
  • 需要用交叉验证而不是直接在同一数据上训练元学习器。

所以集成学习不是“模型越多越好”，而是要看误差是否互补、验证是否可靠。

HW4：大模型合同审阅

HW4 使用 DeepSeek V4 Pro 审阅贷款合同和房屋租赁合同。Prompt 的关键是从相对弱势方视角识别有实质风险的条款，并要求输出严格 JSON：

  • 原始条款。
  • 风险类型。
  • 风险原因。
  • 合同总结。

风险类型包括单方免责、单方权力扩张、过高费用或违约金、自动授权扣款、隐私或数据共享、争议解决不利、冲突或歧义等。

这类任务的重点不是“让模型说得像律师”，而是把输出约束成结构化结果，方便后续审计、展示和人工复核。

LLM 审阅任务的边界

合同审阅是高风险场景，不能把模型输出当法律意见。更合理的定位是：

  • 帮助快速定位可能有风险的条款。
  • 给人工复核提供候选清单。
  • 用统一 schema 便于比较不同合同。
  • 标出冲突、重复和明显不平衡条款。

它不应该：

  • 自动判断合同效力。
  • 代替专业律师。
  • 忽略司法辖区和具体事实。
  • 对所有“不舒服”的条款都报风险。

这和招聘 Agent 的经验类似：LLM 适合做证据整理和初筛，不适合独占最终决策。

这条实验线的共同方法

从 HW2 到 HW4，可以抽出一套共同实验方法：

  1. 明确任务输入和输出。
  2. 固定数据切分或样本口径。
  3. 定义评价指标或输出 schema。
  4. 保存中间结果。
  5. 对模型结果做对照，而不是只看单次输出。
  6. 对高风险任务明确人工复核边界。

传统数据挖掘训练的是模型和指标，大模型应用训练的是流程和约束。两者合在一起，才更接近真实 AI 工程。
