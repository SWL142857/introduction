Agent Memory 与图记忆系统：从论文到招聘场景

发表于2026-06-17|更新于2026-06-17|Research
|浏览量:

Agent 的能力不只取决于单次推理，还取决于它能不能在长期交互中保留有用经验。Memory 研究试图回答一个朴素但困难的问题：系统到底应该记住什么、怎么记、什么时候取出来、如何避免记错。

我的资料里，Agent Memory 主要集中在 科研/memory/、Memory-SRTP/、competition/ 和 bytedance/。前两者偏论文阅读和研究综述，后两者把图记忆落到了招聘业务场景。

记忆不等于聊天记录

最粗糙的记忆方式是把历史对话全部塞回上下文。但这很快会遇到长度、噪声和漂移问题。更合理的做法是把记忆分层：

  • Episodic memory：发生过什么，保留事件和上下文。
  • Semantic memory：抽象出长期稳定的事实和概念。
  • Procedural memory：沉淀可复用的流程、策略和工具调用方式。
  • Reflective memory：从成功和失败中总结原则。
  • Graph memory：用实体和关系组织记忆，支持路径检索和结构推理。

不同论文的命名不完全一样，但核心问题类似：如何从原始交互中提取、压缩、更新和检索记忆。

从 RAG 到 Memory

RAG 更像“外部知识检索”，Memory 更像“系统自身经验的持续组织”。两者有重叠，但关注点不同：

  • RAG 通常面向静态知识库，目标是找对证据。
  • Memory 面向动态交互历史，目标是形成可复用经验。
  • RAG 的单位常常是文档块，Memory 的单位更可能是事件、实体、策略、偏好或关系。

因此，从 RAG 走向 Memory，核心变化是：知识不再只是被检索，而是会被系统持续写入、合并、遗忘和修正。

为什么图适合做 Agent Memory

图记忆的优势在于可以表达关系：

  • 人、任务、工具、文档、决策、错误、偏好都可以成为节点。
  • 相似、依赖、因果、引用、属于、冲突都可以成为边。
  • 检索不再只靠向量相似度，还可以沿着结构路径扩展。

但图也有成本。全局乱连会导致复杂度爆炸，错误边会污染推理，Schema 太死会影响泛化。因此图记忆系统需要先限定场景，再设计最小可用结构。

招聘场景中的 Graph-Based Memory

competition/ 的项目把图记忆落到招聘流程中。系统不是一个简单的简历分类器，而是把招聘过程中的候选人、岗位、特征、历史决策和相似关系组织起来。

核心图结构大致是：

  • JobRole：岗位节点。
  • Candidate：候选人节点。
  • FeatureNode：技能、经验、风险、能力等结构化特征。
  • Candidate-Candidate edge：同岗位候选人相似边。
  • GraphProjectionMemory：基于邻居历史决策计算出的图投影先验。
  • DecisionMemory：历史标签和人工决策记录。

最关键的设计不是“用了图”，而是只在同岗位内部建候选人相似图。这样既符合业务逻辑，也避免全局图边数失控。

Python 算结构，LLM 做解释

这个项目里我最喜欢的一条原则是：

Python 做确定性结构计算，LLM 做解释。

图投影不应该让 LLM 自己拍脑袋判断。更稳的方式是先用 Python 聚合邻居数量、邻居 select/reject 分布、岗位先验、边权平衡等信号，得到 graph_score、projection_label 和 projection_confidence。然后 LLM 读取这些结构化信号，生成自然语言解释。

这样做有几个好处：

  • 可复现：同样输入得到同样结构分数。
  • 可审计：每个分数都有来源。
  • 可替换：后续可以接 GNN、reranker 或新的 projection 策略。
  • 更安全：LLM 不直接拥有最终决策权。

HireLoop：把 Agent 系统接进真实流程

bytedance/ 里的 HireLoop 更进一步，把图记忆和飞书 Base、状态机、人类确认、审计日志接起来。

它的 7-Agent 虚拟组织包括：

  • HR Coordinator
  • Resume Intake
  • Resume Extraction
  • Graph Builder
  • Screening Reviewer
  • Interview Kit
  • Analytics

系统状态从 new 到 decision_pending 可以由 Agent 推进，但 offer / rejected 必须由人类确认。这一点很重要：招聘是高风险场景，Agent 的角色应该是证据整理和流程辅助，而不是自动录用或淘汰。

可复用的系统原则

从这批材料里，我沉淀出几条可复用原则：

  1. 先定义业务对象，再定义记忆结构。不要为了做图而做图。
  2. 所有派生产物保留源 ID，方便回溯。
  3. 结构计算和语言解释分离。
  4. 长任务必须支持 checkpoint、resume、retry。
  5. LLM 抽取结果要做标准化，否则 feature node 会膨胀。
  6. 高风险决策必须有人类最终确认。
  7. 评估不只看模型输出，还要看图质量、检索质量和审计链完整性。

Agent Memory 的难点不是把东西存下来，而是决定哪些东西值得存、存成什么结构、以后如何取出来，并且在错误发生时能定位和修正。
