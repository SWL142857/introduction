我的学习与科研资料地图

发表于2026-06-17|更新于2026-06-17|Learning
|浏览量:

这篇文章不是一个文件清单，而是我给当前工作区做的一次知识整理。原始资料散落在很多文件夹里：课程作业、科研代码、论文 PDF、比赛项目、开源教程、个人材料、实验报告。真正值得长期沉淀的不是“我有多少文件”，而是这些文件背后的学习路径和研究问题。

我把它们整理成六条主线：

  1. 大模型基础与应用
  2. RAG、GraphRAG 与多跳推理
  3. Agent、Memory 与多智能体系统
  4. LLM Systems 与深度学习系统
  5. 图学习、视觉、强化学习与经典课程
  6. 工程项目、数据挖掘与可复现实验

1. 大模型基础：从原理到应用

相关目录：

  • Happy/
  • ANLP/
  • ML/
  • cs224n_gpt/
  • hello-agents/
  • HelloAgents-learn_version/

这一部分的材料构成了一条比较完整的大模型学习路线：

  • 从 NLP 基础、Transformer、预训练语言模型开始，理解 LLM 的模型结构。
  • 通过 ML 课程作业进入 RAG、Transformer、微调、遗忘、模型编辑、模型合并和扩散模型。
  • 通过 ANLP 课件补足语言模型、解码、评估、长上下文、推理、量化、后训练、多模态和 Agent 等专题。
  • 通过 Hello-Agents 系列把知识落到智能体应用：ReAct、Plan-and-Solve、Reflection、上下文工程、记忆、协议、评估和 Agentic RL。

这条线的核心收获是：大模型不是一个单点技术，而是一套从表示学习、训练、对齐、推理、工具调用到系统评估的工程栈。学习时不能只背模型名，更应该追问：输入如何组织、上下文如何管理、工具如何接入、错误如何评估。

2. RAG 与 GraphRAG：从检索增强到结构化推理

相关目录：

  • all-in-rag-main/
  • youtu-graphrag/
  • Efficiency/
  • LoCoRAG/
  • RT-RAG/
  • 科研/RAG/
  • result analysis/

这组材料是当前工作区最明显的研究主线。它覆盖了普通 RAG、复杂检索、多跳问答、图增强检索、社区摘要、Schema 引导图构建、树状推理、评测脚本和结果分析。

我现在对 RAG 的理解可以分成四层：

  • 数据层：文档加载、清洗、分块、元数据组织。
  • 索引层：embedding、稠密检索、稀疏检索、混合检索、向量库和 rerank。
  • 推理层：查询改写、子问题分解、多跳检索、证据聚合、答案生成。
  • 评估层：EM、F1、cover EM、ROUGE-L、LLM judge，以及错误案例分析。

GraphRAG 的关键不只是“把图加进去”，而是用结构约束检索过程：实体、关系、社区、Schema、路径、子图和证据之间要有明确职责。否则图很容易变成昂贵的装饰。

3. Agent Memory：让系统记住什么、怎么记

相关目录：

  • Memory-SRTP/
  • 科研/memory/
  • competition/
  • bytedance/
  • 科研/ToG/
  • 科研/Rel-LLM/

这条线关注的是 Agent 的长期记忆和结构化经验。资料中有大量 memory 论文，包括层次化记忆、图记忆、情景记忆、反思记忆、过程记忆、长期个性化记忆、从 RAG 到 Memory 的非参数持续学习等。

工程上，competition/ 和 bytedance/ 把这个问题落到了招聘场景：候选人、岗位、特征、相似边、图投影、历史决策和 Reviewer/Search RAG 共同组成一个 Graph-Based Memory 系统。

这里最重要的设计原则有三个：

  • 记忆要和业务事件一起产生，而不是事后堆一个数据库。
  • Python 负责确定性结构计算，LLM 负责解释和语言化输出。
  • 人类最终决策要留在环内，Agent 负责整理证据、提出建议和生成审计记录。

4. LLM Systems：从模型使用到系统实现

相关目录：

  • cmu11868/
  • cmu11766/
  • homework_spring2026/
  • CS185:285/
  • RL-notes/

这条线偏系统与训练基础。cmu11868 覆盖了 MiniTorch、自动微分、CUDA kernel、Transformer、分布式训练、DeepSpeed ZeRO、LoRA、SGLang、VERL 和 RLHF。它让“调用模型 API”往下沉了一层：模型为什么慢、显存为什么炸、并行如何切、KV cache 怎么复用、训练和推理系统如何分工。

RL-notes 和 CS185:285 则负责把强化学习、离线强化学习、RLHF、LLM 后训练和决策理论串起来。对于 Agent 研究来说，这很重要，因为 Agent 不只是会聊天的程序，它本质上仍然是在不确定环境里选择行动的系统。

5. 图学习、视觉与经典课程基础

相关目录：

  • cs224w/
  • cs231n/
  • GAMES101/
  • Data Mining/
  • 大二下/
  • 大三上/
  • Compiler/
  • cp-3230101959/

这一部分是基础能力的底座：

  • CS224W 训练图结构、图神经网络和网络分析直觉。
  • CS231n 覆盖 KNN、softmax、两层网络、全连接网络、CNN、BatchNorm、Dropout、RNN、Transformer Captioning、CLIP、DINO、DDPM 和自监督学习。
  • GAMES101 带来图形学和几何基础。
  • 编译、MiniSQL、网络实验、C++ 数据结构等材料补足系统与底层实现能力。

这些内容看起来和 LLM 应用距离较远，但它们决定了工程判断的厚度。很多 RAG、Agent 和图记忆问题，最后都会回到数据结构、复杂度、并发、评估和可复现性。

6. 工程项目与可复现实验

相关目录：

  • project/
  • reproductive-ai-mining-assignment/
  • Data Mining/final/
  • repo-group6-grade/
  • vibe-vibe-main/
  • guizang-ppt-skill-main/
  • awesome-design/
  • awesome-design-md-main/
  • Big Data/
  • report/

这部分不是单纯学习，而是把方法做成可交付成果。

例如，生殖医学 AI 文献信息挖掘项目把任务拆成期刊白名单、多源召回、去重合并、规则筛选、大模型复核和 CSV/报告导出。它的价值不只在最终有多少篇论文，而在于可复现流程：每一步都有输入、输出、脚本、口径和中间文件。

再比如，bytedance/ 里的 HireLoop 把比赛系统推进到真实飞书 Base、API 写回、状态机、人类确认和安全边界。这类项目训练的是“系统能不能闭环”，不是“demo 能不能看起来聪明”。

不适合公开发布的内容

有些目录应该只作为私有归档，不适合直接发布到博客：

  • material/：个人事务材料与申请类文件。
  • 含真实凭据、个人身份信息、未脱敏数据的实验输出。
  • 第三方课程作业的完整答案、私有数据、未授权论文全文。

博客里可以写方法论和学习总结，但不要把个人材料或受限内容原样公开。

后续整理原则

我会按“主题文章”继续整理，而不是按文件夹逐个搬运。一个好的博客知识库应该回答：

  • 我在研究什么问题？
  • 这个问题为什么重要？
  • 我读过/做过哪些路线？
  • 每条路线的关键机制是什么？
  • 哪些经验可以复用到下一个项目？

文件夹只是入口，知识结构才是长期可读的东西。
