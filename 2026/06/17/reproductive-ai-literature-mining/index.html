一次可复现的生殖医学 AI 文献挖掘流程

发表于2026-06-17|更新于2026-06-17|Project
|浏览量:

这个项目的目标很具体：整理 2022-2026 年发表、2025 年影响因子大于 10、主题属于妇产科学/生殖医学并明确涉及 AI 技术的论文，最终输出固定 5 列 CSV：

  • 论文标题
  • 发表期刊
  • 发表年份
  • 2025 年期刊影响因子
  • 论文使用的 AI 技术

原始资料主要在 project/、reproductive-ai-mining-assignment/ 和 Data Mining/final/。

这件事看起来像“搜论文”，但真正有价值的是流程设计：如何让召回、筛选、复核和导出都可复现。

阶段一：建立期刊白名单

第一步不是直接搜论文，而是先定义“高影响力期刊”的边界。项目用公开可访问的期刊排名页建立 2025 年影响因子大于 10 的期刊白名单。

这里有一个重要口径：领域限定发生在论文主题层面，而不只是在期刊分类层面。也就是说，Nature、JAMA Network Open、npj Digital Medicine、Medical Image Analysis 等综合或交叉期刊中，只要论文主题属于妇产科/生殖医学，也应该被纳入候选。

这个设计保证了召回不被传统期刊分类卡死。

阶段二：多源召回候选论文

主数据源是 PubMed E-utilities，补充数据源包括 Crossref Works API 和 Semantic Scholar Graph API。

PubMed 检索同时限制：

  • 期刊在高影响因子白名单中。
  • 发表时间在 2022-01-01 到 2026-12-31。
  • 标题或摘要命中妇产科/生殖医学相关关键词。
  • 标题或摘要命中 AI 相关关键词。

Crossref 主要负责补漏，尤其是 DOI 记录和 PubMed 标引不完整的论文。Semantic Scholar 则可以作为增强源，补充引用、摘要或外部元数据。

多源召回的关键不是“源越多越好”，而是每个源都要有清楚的职责。

阶段三：合并去重

候选合并时优先按 DOI 去重；如果没有 DOI，再按标题、期刊和年份去重。合并过程中还会补充缺失摘要、PMID 和外部链接。

这一步非常容易被低估。文献挖掘里的重复项不只是完全相同标题，还包括大小写差异、标点差异、期刊缩写差异、提前在线发表与正式发表年份差异。去重规则越清楚，最终结果越可解释。

阶段四：规则筛选

规则筛选负责高召回和可复现，不追求完美精准。它检查：

  • 期刊是否在白名单中。
  • 标题/摘要是否命中医学主题。
  • 标题/摘要是否命中 AI 技术术语。
  • 文章类型是否属于应排除类别，比如 Editorial、Comment、Letter、News、Erratum。

AI 技术标签包括 machine learning、deep learning、CNN、Transformer、NLP、LLM、computer vision、radiomics、random forest、SVM、gradient boosting 等。

规则筛选的好处是透明，坏处是容易误收和漏收。所以它适合作为第一层，而不是最终裁判。

阶段五：大模型复核

第二轮使用大模型复核候选论文，判断它们是否真正满足主题、年份、期刊和 AI 技术要求。

这一步的价值是处理边界样本：

  • 标题有 AI 关键词，但论文主体不是 AI 方法。
  • 论文属于医学 AI，但不是妇产科/生殖医学。
  • 摘要提到统计模型，但不构成 AI 技术。
  • 研究是评论、指南或新闻，不应纳入实证论文结果。

大模型复核不能替代规则和数据源，它更像一个高成本的语义过滤器。为了可复现，复核结果需要缓存，并导出中间 JSON/CSV。

阶段六：导出和报告

最终产物包括：

  • 最终 CSV。
  • 期刊白名单。
  • PubMed / MeSH / Crossref / Semantic Scholar 候选。
  • 合并候选。
  • LLM 复核缓存。
  • 规则和大模型筛选后的结果。
  • Markdown / LaTeX 报告。

这一点很重要：可复现实验不是只有最终表格，还应该保留中间产物。否则一旦结果被质疑，很难解释某篇论文为什么进入或被排除。

这个项目沉淀的方法论

我从这个项目里学到的不是某个 API 的用法，而是一套适合信息挖掘任务的通用流程：

  1. 先定义口径，再写脚本。
  2. 先建立白名单或边界条件，再召回候选。
  3. 多数据源要分工明确。
  4. 去重规则要优先使用稳定 ID。
  5. 规则筛选负责可复现，大模型负责语义边界。
  6. 所有中间文件都要落盘。
  7. 最终报告必须解释数据来源、筛选逻辑和排除标准。

这套流程可以迁移到很多领域：产业报告挖掘、论文综述、竞品分析、医学证据整理、政策文本分析。关键不是“让 LLM 帮我找资料”，而是把 LLM 放进一个有边界、有缓存、有审计的流程里。
